Architettura di Sistema

I bot monolitici falliscono durante l'alta volatilità. Helmsman Trading si basa su un'architettura a 5 livelli decentralizzata e disaccoppiata progettata per una resilienza senza compromessi.

Layer 1

Il Data Lake

Dipendere dalle API REST per ogni calcolo degli indicatori introduce rischi di latenza di rete e rate-limit. Il Data Lake L1 acquisisce nativamente i dati dai provider SIP (Polygon, IEX) e li convoglia in una cache SQLite e memoria locale ultraveloce.

  • VWAP e Medie Mobili locali calcolati a costo di rete zero.
  • Historical Replay immediato per il backtesting offline.

@register_skill(name="MomentumBreakout")
class Breakout(BaseSkill):
    def on_data(self, data):
        if data.price > data.vwap * 1.02:
            self.buy("AAPL", qty=100)

Layer 2

Plugin Decentralizzati

Non dovresti dover forkare un framework per aggiungere una strategia. Helmsman usa un registro dinamico dei plugin. Basta scrivere una classe Python, decorarla con @register_skill e inserirla nella cartella. Il motore la scoprirà e la eseguirà in una sandbox isolata.

Vedi Guida per Sviluppatori

Layer 4

Il Guardiano del Rischio

Non è questione di se la tua strategia farà un errore, ma di quando. Il Risk Engine L4 si interpone direttamente tra la tua logica e il mercato. Applica rigorosamente limiti globali di esposizione massima, stop loss dinamici e regole di trading.

Se una strategia tenta di aprire una posizione che eccede la tua tolleranza al rischio definita, L4 bloccherà silenziosamente l'esecuzione e ti avviserà. Il tuo capitale è protetto.

Layer 5

Ponte Broker

Helmsman astrae le API disordinate dei broker usando rigidi schemi Pydantic. Scrivi la tua strategia una volta e distribuiscila ovunque cambiando solo un flag nel `.env`.

PaperSim

Motore di backtesting 100% offline e locale. Nessuna API key richiesta.

Alpaca

Integrazione completa con le API Alpaca V2 per il Paper e Live trading.

Tradier

Integrazione diretta per il trading avanzato di opzioni ed azioni.
