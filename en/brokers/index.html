An adapter is not a logo

Putting Interactive Brokers, Directa or Schwab on a page is an afternoon of CSS. Getting a stop-attached entry there is a contract, a payload, a session clock, a way to read the order list. Alpaca wants brackets and OTO, a helmsman_… client id. Tradier wants OTOCO in a form payload, a hyphenated tag, a bearer token. Idempotency, a closed cash session, how a stop is reconciled: all different.

Paste Alpaca onto Tradier and you open naked while calling the mess «multi-broker». Helmsman does not pretend the world is one API. Every adapter carries its own engagement card: how you enter, how you must not, what happens when the session is closed. You stay a client of whoever gives you the book. We lengthen the bridge, venue by venue — and only if the venue exposes an API the model can respect.

In code today: Alpaca (paper), Tradier (sandbox), IG (demo) and Interactive Brokers (mock-tested, live pending), plus PaperSim locally to prove the rules with the network off. Saxo, OANDA, lemon.markets: next. Then Schwab, cTrader, Tiger, Tradovate, Questrade, MetaApi and the other APIs that fit. Directa, eToro, Trading 212, moomoo: integrable, with friction. Fineco, DEGIRO, Robinhood, Fidelity, Trade Republic, Plus500: no official retail trading API — we will not fake them with a sticker.

The marks you see belong to their owners. They name the venues; they do not sell a partnership that does not exist. Gold on the tile = bridge already in code. Grey = to build. Amber = with friction. No fake «certified integration».

Four adapters. Four grammars.

The same human yes. The same cover. Different payloads. If the bridge does not respect the venue, it is not a bridge: it is a bug with a logo.

ADAPTER · PAPER

Alpaca

First live bridge. Brackets and OTO, a traceable client id. The adapter is paper: a seat, when there is one, is for clients. This is where we learned that «covered» is an order class, not a promise in chat.

  • — OTO / bracket, not SIMPLE
  • — Human confirm before submit
  • — Engagement rules on the adapter, not the LLM

ADAPTER · SANDBOX

Tradier

Second real broker. OTOCO in a form payload, a sanitised tag, sandbox. It proved the thesis: copy Alpaca here and you open naked. So we do not copy it.

  • — OTOCO, not a dressed-up bracket
  • — Tags without underscores
  • — The same preview → confirm loop

ADAPTER · DEMO

IG

Third bridge. The adapter is done: it runs in demo. Live is a key, not another craft. Same thesis as Tradier: its own CFDs and sessions, no Alpaca paste.

  • — Demo already in code
  • — Live = credentials, not a rewrite
  • — CFD grammar, not US equity

ADAPTER · MOCK

Interactive Brokers

Fourth bridge. Mock-tested: the gateway is there, go-live is not. IBKR is not brochure REST: it is TWS/Gateway on the machine. That is why live stays pending until covers and session are honest.

  • — Adapter done, not a sticker
  • — Live pending
  • — Local gateway, not a pasted JSON

PaperSim stays the bench: no keys, no network, so the rules can fire before a venue is touched. It is not a broker. It is the workshop.

What stays off the slide

Helmsman does not reverse-engineer the browser and does not break ToS. If there is no official retail trading API, the name does not run on the marquee.

What we will not do

  • We will not move your book onto an omnibus account of ours. We are not your broker.
  • We will not sell a «partner» venue as the only way to use Helmsman.
  • We will not go live on a venue until covers and engagement rules are honest there.
  • We will not paste Alpaca’s rules onto everyone. Tradier already proved it: respect the venue, or lie.
  • We will not fake an adapter where the API is missing, or where the ToS forbid it.

What we ask

On the pre-registration, name the broker you already use. It is not a pitch to open a new account. It is the queue: Saxo, OANDA, lemon.markets, Directa or IBKR tell us where to lengthen the bridge after the four already in code. If you trade from Fineco or DEGIRO, say so anyway: we know the bridge is not there.

Your yes stays the same. Only who receives the covered order changes — and only if that who exposes an API. That is the only invariant we are selling you.
